# Make prepared Bootstrap writes deterministic

Type: task
Status: resolved
Spec: ../spec.md#shared-replica-conformance

## Outcome

Generate byte-stable shared conformance histories for multi-Item Bootstrap/Import plans without
changing atomic Replica semantics.

## Original gap

`replica/persistence_contract.rs::bootstrap_rows` iterates HashMaps, and `bootstrap_write_diff`
preserves that iteration order. Equivalent multi-Item plans can emit different prepared-write arrays.
`replica/replica_conformance.rs::import_operation` previously used one Item per shared Import batch,
leaving multi-Item prepared-write behavior uncovered. Both paths are under
`packages/client-runtime/crates/bittery-client-core/src`.

## Decision frontier

Decide whether stable prepared-write order is a shared persistence-contract promise or only a
generator reproducibility property. Either choice must preserve atomic semantics; order itself
has no Domain meaning. Sorting inside the generator is sufficient if only generated bytes need
stability; sorting the contract also makes order available to other consumers. The maintainer
selected generator-only canonicalization below.

Ticket 38 owns physical migrations and does not require this ordering promise or a dependency.

## Work after the decision

Maintainer decision (2026-09-07): canonicalize generated histories only, by store/key. Prepared-write
ordering is not a shared persistence-contract guarantee and has no Domain meaning. Ticket 38 does
not require this ordering or a new dependency. Full CI is waived; focused conformance and generation
checks remain required.

- Canonicalize at the selected boundary by store and key without changing effects or guards.
- Remove the one-Item corpus workaround and add a multi-Item plan/history.
- Cover insertion-order permutations and independently constructed equivalent maps; two calls using
  the same HashMap can share its order and are not a reliable reproducer.
- Prove repeated generator `--check` runs are stable, with no semantic corpus changes.
  Run focused Core/shared-adapter conformance, generated checks, `pnpm check:ci:rust`,
  and `git diff --check`.


## Implementation and review

Generated Install/Commit writes now sort stably by store and Account/record key at the corpus
boundary. Same-key Put/Delete order, guards, payloads, and the production persistence contract stay
unchanged. Import histories carry five- and two-Item applied batches plus a later rejected batch;
one Bootstrap page carries all five categories. Seven other histories differ only in write ordering.

Verified: independently seeded map/insertion permutations and effect/guard regressions; Core
conformance (5), corpus assertions (4), IndexedDB histories including migrated checkpoints (2),
InMemory/SQLite execution, Core Clippy, Rust formatting, and `git diff --check`. Generation check plus
eight independent `--check` processes passed. Full CI was waived and not run. Independent Standards
and Spec review approved the change and repeated Core, corpus, IndexedDB, and eight generation checks.

## Simplification pass

A full delegated pass and independent review found no beneficial further reduction. The private
canonicalization function already shares key/order helpers and keeps policy local to the generator.
Further extraction would add complexity or weaken the accepted generator-only scope; no code changed.
