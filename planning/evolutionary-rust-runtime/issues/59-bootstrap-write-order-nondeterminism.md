# Make prepared Bootstrap writes deterministic

Type: task
Status: needs-info
Spec: ../spec.md#shared-replica-conformance

## Outcome

Generate byte-stable shared conformance histories for multi-Item Bootstrap/Import plans without
changing atomic Replica semantics.

## Current gap

`replica/persistence_contract.rs::bootstrap_rows` iterates HashMaps, and `bootstrap_write_diff`
preserves that iteration order. Equivalent multi-Item plans can emit different prepared-write arrays.
`replica/replica_conformance.rs::import_operation` therefore uses one Item per shared Import batch,
leaving multi-Item prepared-write behavior uncovered. Both paths are under
`packages/client-runtime/crates/bittery-client-core/src`.

## Decision frontier

Decide whether stable prepared-write order is a shared persistence-contract promise or only a
generator reproducibility property. Either choice must preserve atomic semantics; order itself
has no Domain meaning. Sorting inside the generator is sufficient if only generated bytes need
stability; sorting the contract also makes order available to other consumers. Neither choice is
accepted yet.

Ticket 38 owns physical migrations. Confirm whether it needs the ordering promise before adding a
dependency; this ticket currently has none.

## Work after the decision

- Canonicalize at the selected boundary by store and key without changing effects or guards.
- Remove the one-Item corpus workaround and add a multi-Item plan/history.
- Cover insertion-order permutations and independently constructed equivalent maps; two calls using
  the same HashMap can share its order and are not a reliable reproducer.
- Prove repeated generator `--check` runs are stable, with no semantic corpus changes.
  Run focused Core/shared-adapter conformance, generated checks, `pnpm check:ci:rust`,
  and `git diff --check`.
