# Rotation plans coordinate Vault key rotation

Bittery performs Vault key rotation through a short-lived, server-recorded Rotation plan rather than an untracked read followed by a large write. One plan belongs to one Vault and fixes the initiating User, reason, expected key version, Member set, Item versions and Attachment-envelope state; clients fetch its input and upload encrypted results in bounded pages, and finalization revalidates and atomically consumes every plan required by the calling policy module. Plans expire after 30 minutes of inactivity, never live longer than 24 hours, are single-use, and do not lock ordinary Vault writes while preparation is in progress.

The shared client rotation module owns the ceremony and a fresh opaque in-memory `KeyRef`; the server Vault key rotation module owns plan state, validation, rotation records, SQL and Sync events. Member departure and Vault membership remain separate policy modules over that mechanism. This split gives Key rotation one interface without letting cryptographic mechanics decide whether a departure or removal is authorized, preserves server SQL ownership from ADR-0002, and leaves manual rotation as a future policy caller rather than part of this change.

Attachments use per-Attachment keys wrapped by the Vault key. Rotation therefore rewraps Attachment keys instead of downloading and rewriting object-storage blobs. Because Bittery has no deployed users or Attachment data, this is a clean format cutover with no legacy read path.

For a multi-Vault Member departure, every Rotation plan is finalized in the same transaction as Team reassignment, Session revocation records, audit and Sync events. Any stale Vault, Member, Item or Attachment state aborts the entire departure. Billing seat synchronization remains best-effort after commit because it crosses an external seam. Idempotent command replay returns the original committed outcome; after server success, clients fail closed and refresh authoritative local state rather than treating a local persistence failure as a failed rotation.
