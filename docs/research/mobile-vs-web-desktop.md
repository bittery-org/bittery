# Mobile parity review: web and desktop

## Scope and method

This is a static, primary-source review of the product surfaces implemented in
`apps/web`, `apps/desktop`, and `apps/mobile` on 2026-08-08. A **confirmed
gap** means that a workflow is implemented in web and/or desktop source and
there is no corresponding mobile route, component, or invocation in the mobile
application source reviewed. It does **not** assert that the backend lacks the
operation. An **uncertain/inferred gap** has strong UI evidence but could be
served by an operating-system surface or code outside the mobile app route
tree.

"Device" follows the project vocabulary: the device list is a session list, so
revoking a device revokes its session. "Account", "vault", "Secret Key", and
other terms have the meanings defined in [CONTEXT.md](../../CONTEXT.md#identity).

## Practical priority order

1. Restore core account safety on mobile: recovery/sign-up, account-security
   changes, and remote device/session revocation.
2. Make vault management functional: implement vault creation/deletion and item
   moving; then add shared-vault/team administration where entitlements permit.
3. Add portability and commerce: import/export, email-restricted shares, and
   billing handoff/visibility.
4. Add differentiated management surfaces: Travel mode controls, Sentinel,
   dashboard, advanced cache recovery, and passkey management UI.
