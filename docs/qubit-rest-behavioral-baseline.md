# Qubit-to-REST behavioral baseline

Status: implementation inventory for the pre-launch big-bang cutover. This document describes the code in the current branch; it is not the OpenAPI contract.

## Scope and verification

The registration graph in `apps/server/src/lib.rs` and `apps/server/src/rpc/*.rs` contains **113 handlers: 45 queries and 68 mutations**. Production TypeScript (all `apps/**` and `packages/**` `.ts`/`.tsx`, excluding generated code, tests and specs) references **99 distinct procedures: 38 queries and 61 mutations**. The REST OpenAPI surface has 100 operations, including the separately registered non-Qubit `/api/meta` and sync-SSE operations; route coverage tests are the exact source of truth. The remaining **14 procedures have no production call through `.query`, `.mutate`, `.queryKey` or `.queryOptions`** and are intentionally deleted rather than ported:

`healthCheck`, `privateData`, `auth.heartbeat`, `auth.logout`, `auth.logoutAll`, `billing.syncSeats`, `share.get`, `share.update`, `sync.checkConflict`, `sync.acknowledgeEvents`, `sync.getLastAcknowledged`, `sync.getSyncState`, `team.members.deleteAccount`, and `vault.members.lookupUser`.

The counts match the architecture decision with no discrepancies. The inventory was checked against both the Rust router registrations and the generated `QubitServer` shape. Dynamic reconstruction in `packages/shared/src/rpc-client.ts` does not hide additional procedure calls.

## Reading the tables

- `Q` and `M` are the current Qubit query and mutation kinds; the REST column is the replacement.
- `Open`, `Public-auth`, and `Session` mean `AppContext`, `PublicAuthContext`, and `RefreshSessionContext`. `Session` always requires a verified bearer session; the service then applies the resource rule shown. Public-auth adds request metadata and public-auth abuse controls, but no session.
- Every `Session` row can fail with `UNAUTHORIZED`. Every database, storage, email, or Stripe operation can fail with a redacted `INTERNAL_SERVER_ERROR`. The errors column lists the additional, behaviorally meaningful current `AppError` classes: `BAD_REQUEST`, `NOT_FOUND`, `FORBIDDEN`, `CONFLICT`, and `TOO_MANY_REQUESTS`.
- `SSE` means the handler calls `NotifySyncExt`, so a successful service result wakes authenticated sync streams after the service has persisted sync events. `Local` means the named caller updates or invalidates its own query/cache state. Read-only consumers are listed to preserve query-key and call-site coverage.
- Types are the current Rust service boundary types. Path parameters replace identifier-only input wrappers. REST handlers must use dedicated transport DTOs rather than exporting these service types directly.
- All authenticated and authentication-related replacements are `no-store`. Command paths are used where CRUD semantics would be dishonest. One-time raw tokens returned by share-link creation and invitation send/resend must not be idempotency-replayed.

## Cutover implications captured by the baseline

1. Service functions remain the authorization and SQL authority per ADR 0002. REST handlers must be thin DTO/extractor adapters and must not reproduce these rules in a repository tier.
2. Signup/recovery verification codes, invitation tokens and share-link tokens remain digest-only per ADR 0003. `share.create`, `team.invitations.send`, and `team.invitations.resend` disclose a raw token exactly once.
3. Shared-core call sites remain the single behavior path for web, desktop, mobile and extension per ADR 0008. The REST facade must replace the current client without moving domain behavior into individual apps.
4. The current client-side invalidation registry in `packages/sync/src/query-invalidation.ts` covers vault, item, member and travel-mode sync events. The REST facade must provide stable domain query keys for those same invalidations; generated OpenAPI `paths` must not become query keys outside `packages/api-contract`.
5. The currently used unbounded list calls (`vault.list`, `listItems`, `listAllItems`, `listAllDeletedItems`) cannot be copied literally. Their consumers must iterate bounded pages or read the staged offline cache. This is a behavior-preserving migration at the screen level, not a wire-shape preservation requirement.
6. The Rust handler inventory contains no subscriptions. SSE remains the sole realtime hint transport; generic JSON-RPC batching and WebSocket lifecycle have no behavior to preserve.
