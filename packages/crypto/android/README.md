# @bittery/crypto-android

The Rust crypto core, compiled for Android and reachable from Kotlin. It is the native sibling of
`packages/crypto/wasm`: same `bittery-crypto-api` crate, a different binding target.

Its one consumer is the Tauri credential provider
(`apps/mobile/src-tauri/plugins/credential-provider`), which runs in a separate Android
process from the WebView and so cannot use the WASM build. Everything else on mobile goes through
WASM.

## What is here

| Path | Tracked? | What it is |
| --- | --- | --- |
| `generated/java/uniffi/bittery_crypto_api/` | yes | UniFFI Kotlin bindings — a JNA-based contract, reviewable in a diff |
| `generated/jniLibs/<abi>/libbittery_crypto_api.so` | no | The compiled Rust library, one per ABI |

Both are generated. Never hand-edit either (ADR 0012), and never hand-copy them into an app —
the consumer reaches them with a Gradle `srcDir`.

## Building

```sh
pnpm run build:crypto-android
```

Needs the Android NDK. The script uses `$ANDROID_NDK_HOME`, `$ANDROID_NDK_ROOT` or `$NDK_HOME` if
one is set, and otherwise picks the highest version installed under `$ANDROID_HOME/ndk`.

The Kotlin is generated by `crates/uniffi-bindgen`, a wrapper pinned to the exact `uniffi` version
the crate links against. It replaced `uniffi-bindgen-react-native`, which produced byte-identical
Kotlin but dragged a React Native package along with it.
