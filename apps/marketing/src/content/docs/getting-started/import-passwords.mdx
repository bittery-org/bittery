# Import Your Passwords

Switching to Bittery is painless. Import your 1Password, Bitwarden or KeePassXC vault, or your saved Chrome or Firefox passwords, in just a few steps — more sources are on the way.

## Supported import sources

| Source | Format | Status |
|--------|--------|--------|
| **1Password** | 1PUX | Supported |
| **Bitwarden** | CSV / JSON | Supported |
| **Chrome / Chromium** | CSV | Supported |
| **LastPass** | CSV | Coming soon |
| **Dashlane** | CSV | Coming soon |
| **Firefox** | CSV | Supported |
| **Safari / Keychain** | CSV | Coming soon |
| **KeePassXC** | CSV | Supported |
| **KeePassXC / KeePass** | KDBX | Coming soon |
| **KeePass 1.x** | CSV | Coming soon |

## How to import

<Steps>
<Step title="Export from your current manager">
In your current password manager, find the **Export** option (usually in Settings), then pick the format Bittery supports for that source.

- **1Password** — export as **1PUX**. It carries the most data, including custom fields and one-time password secrets.
- **Bitwarden** — export your **individual vault** as **.json** (recommended) or **.csv**. JSON also carries cards, identities and password history. Turn **off** password protection / encryption for the export, and do not include attachments — Bittery cannot read encrypted exports or attachment ZIPs.
- **Chrome / Chromium** — go to **Settings → Passwords and autofill → Google Password Manager → Settings**, then **Download file** under *Export passwords*. In Chrome you can jump straight there with `chrome://password-manager/settings`; Chromium builds without Google Password Manager expose the same **Export passwords** option under **Settings → Autofill and passwords → Password Manager → Settings**. Chrome exports logins only: passkeys, one-time password secrets and any grouping are not part of the file, so they cannot be imported. Chrome also writes one row per affiliated site, so a credential saved for several domains arrives as several items.
- **Firefox** — open `about:logins`, use the **⋯** menu and choose **Export Logins…**. Firefox writes a `logins.csv` containing only your saved website logins.
- **KeePassXC** — open your database, then choose **Database → Export → Export to CSV…** (the `keepassxc-cli export --format csv` command writes the same file). Bittery reads the export from **KeePassXC 2.0 or newer**; 2.6.3 and newer also export one-time password secrets. Empty the **Recycle Bin** before you export — KeePassXC writes deleted entries into the file alongside live ones and puts no marker on them, so they arrive as an ordinary group you would have to skip by hand.

<Callout type="note">
Firefox's export is deliberately narrow: it has no item names, no notes, no folders and no one-time password secrets, so there is nothing for Bittery to import beyond the address, username and password. Bittery names each item after the website it belongs to, and keeps the authentication realm of an HTTP-auth login as an **HTTP Realm** field. Firefox's internal metadata — the form action origin, the item's GUID and its created / last-used / password-changed timestamps — is not carried over. If you are signed in to Firefox Sync, the export also contains a `chrome://FirefoxAccounts` entry holding your sync keys rather than a password; Bittery skips it and tells you so in the preview.
</Callout>

<Callout type="note">
KeePassXC's CSV holds the group, title, username, password, address, notes and — from 2.6.3 on — the one-time password secret. Everything else your database can store is simply not in the file: custom attributes, file attachments, tags, expiry dates and password history are not exported by KeePassXC and therefore cannot be imported. The entry icon and the created / modified timestamps are in the file but are not carried over, since Bittery has nowhere to put them. A Steam one-time password imports its secret but not its custom alphabet, so Bittery's codes will differ from KeePassXC's — the preview flags each entry this affects. If you need attachments or custom fields, export from **1Password** or **Bitwarden** instead, or wait for the KDBX importer.
</Callout>

<Callout type="warning">
Take the CSV export from KeePassXC itself, not from KeePass 1.x or KeePass 2 — their CSV layouts are different files with different columns, and Bittery rejects them rather than guessing at which column means what.
</Callout>

<Callout type="warning">
The export file contains unencrypted passwords. Delete it immediately after importing into Bittery.
</Callout>
</Step>
<Step title="Open Bittery import">
In the Bittery web app or desktop app, go to **Settings → Import** and select your source.
</Step>
<Step title="Upload your file">
Select the exported file. Bittery will parse it and show you a preview of the items to import.
</Step>
<Step title="Review and confirm">
Review the detected items, then map each source vault to a Bittery vault — either a new one or an existing one. Bitwarden folders show up here as source vaults; items without a folder are grouped together. Neither Chrome nor Firefox has folders, so their items arrive as a single **Chrome Passwords** or **Firefox** source vault respectively.

KeePassXC groups show up as source vaults too. Bittery's vaults are flat, so a nested group keeps its path in its name — `Work/Servers` stays one vault rather than being merged into `Work`. Entries that sit directly in the database's top-level group arrive under **No Group**.
</Step>
<Step title="Done">
All items are encrypted client-side and stored in your vault. The imported data never leaves your device unencrypted.
</Step>
</Steps>

## After importing

- Verify a few logins work correctly by visiting the websites
- Organize items into folders if desired
- Delete the exported file from your computer
- Consider removing passwords from your old manager once you're confident
